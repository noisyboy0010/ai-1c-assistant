# ИИ-ассистент для 1С: ответы по живой базе и по инструкциям

Telegram-бот для руководителя и сотрудников компании на 1С:Бухгалтерии 3.0.

- **Руководителю** он отвечает по живой базе: «кто нам должен?», «просроченные долги», «сколько должна Ромашка на 1 ноября?», «продажи за октябрь», «остаток фильтр масляный», «залежавшиеся товары».
- **Сотрудникам** он отвечает по инструкциям к доработкам 1С и показывает, из какой инструкции взят ответ. Если ответа в инструкциях нет — так и говорит.

> Демо-видео: _ссылка будет добавлена_

## Задача

| Было | Стало |
|---|---|
| Чтобы узнать долги или продажи, руководитель просит бухгалтера сделать отчёт | Пишет вопрос в Telegram и через несколько секунд получает цифры на текущую минуту |
| Сотрудники задают консультанту одни и те же вопросы: «где кнопка», «что значит ошибка» | Бот отвечает по инструкциям со ссылкой на источник |
| Доработки 1С ломаются при обновлении типовой конфигурации | Все доработки сделаны расширениями (.cfe), типовая конфигурация не меняется |

## Как устроено

```
Telegram ─► маршрутизатор ─┬─ вопрос про данные ─► проверенный запрос к 1С (COM, только чтение) ─► ответ с цифрами
                           └─ вопрос про работу ─► поиск по инструкциям (BM25 + векторы, RRF) ─► Claude ─► ответ + источник
```

**Ответы по данным 1С** (`bot/data1c.py`)
- На каждый вопрос делается свежий запрос к базе, старые выгрузки не используются.
- Из вопроса извлекаются только параметры: дата («на 1 ноября»), период («за прошлый месяц»), контрагент (с учётом падежей: «Северной ГЭС» → «СЕВЕРНАЯ ГЭС-2 АО»), товар.
- Запросы к базе написаны заранее и сверены с 1С. Нейросеть их не генерирует.
- Учтена бухгалтерская специфика:
  - непроведённые документы не попадают в долг, и бот предупреждает о них;
  - переплаты покупателей показываются отдельно;
  - просрочка считается только по реализациям;
  - минусовые остатки помечаются как ошибка учёта.

**Ответы по инструкциям** (`bot/rag.py`) — RAG с гибридным поиском:
- **BM25** с русским стеммингом — поиск по точным словам.
- **Эмбеддинги** (`potion-multilingual-128M`, работают на процессоре) — поиск по смыслу: «не грузится эксель» находит «загрузку из Excel».
- **Слияние двух поисков** через Reciprocal Rank Fusion.
- **Решение «отвечать или нет»** в три зоны: уверенный отказ, серая зона (решает модель), уверенный ответ.

**Доработки 1С** (`1c-tools/`)
- Расширение «Загрузка счетов покупателям из Excel»:
  - автоматически сопоставляет колонки файла с полями счёта;
  - проверяет ИНН;
  - защищает от повторной загрузки тех же счетов.
- Расширение «Залежавшиеся товары» — отчёт: сколько денег заморожено в товаре без продаж и по каким позициям.
- XML расширений генерируется Python-скриптами (`tools/gen_ext*.py`), логика проверяется тестами.
- `onec.py` — подключение к 1С через COM: запросы, метаданные, выгрузка в CSV.

## Результаты

| Что проверялось | Результат |
|---|---|
| Итог долгов по счёту 62 против выгрузки из 1С | Совпал до копейки |
| Маршрутизация: вопросы по инструкциям не должны уходить в данные | 54 из 54 |
| Нужная инструкция на 1-м месте, контрольный набор (новые вопросы) | 7/10 только BM25 → **10/10** с векторным поиском |
| Бот берётся отвечать на вопросы по теме, контрольный набор | 7/10 → **10/10** |

Пороги подбирались на одном наборе вопросов (`TUNE_*` в `eval.py`), качество оценивалось на другом (`TEST_*`).

## Ошибки ИИ, которые я нашёл

Код писался с Claude Code. Логику, требования и проверку результатов делал я. Три ошибки ИИ, которые прошли бы незамеченными без проверки на реальных данных:

1. **Бизнес-логика.** ИИ считал просрочку по всем строкам счёта 62. В «просроченный долг покупателя» попали списания с расчётного счёта, то есть наши платежи контрагенту, и просрочка была завышена на ~10%. Тесты при этом проходили. Нашёл сверкой с документами в базе.
2. **Переобучение порога.** Порог отказа подбирался и проверялся на одних и тех же вопросах: 25 из 25. На новых вопросах бот отказал на 3 из 10 нормальных. Исправлено: отдельный контрольный набор и «серая зона».
3. **Маршрутизация.** «Как выгрузить дебиторскую задолженность в CSV?» уходил в расчёт долгов вместо инструкции. Пойман тестом; правило «как / где / почему → инструкции».

## Безопасность

- Пользователь 1С только на чтение. Проверено программно через `ПравоДоступа`: изменение, создание и проведение документов запрещены.
- Нейросеть не пишет запросы к базе. Это исключает и инъекции, и уверенно неверные суммы.
- Бот отвечает только Telegram ID из `allowed_users.txt`.
- Секреты хранятся в Windows Credential Manager или `.env`, в репозиторий они не попадают (см. `.gitignore`).
- В репозитории нет данных реальных компаний: все контрагенты в тестах и примерах вымышленные.

## Запуск

```bash
cd bot
pip install -r requirements.txt
python test_data1c.py                  # тесты маршрутизации (база 1С не нужна)
python eval.py                         # качество поиска по инструкциям
python data1c.py "кто нам должен"      # вопрос по данным (нужна база 1С и 1c-tools/.env)
python bot.py                          # Telegram-бот
```

Подробная инструкция для пользователя без опыта программирования — в [bot/КАК-ПОЛЬЗОВАТЬСЯ.md](bot/КАК-ПОЛЬЗОВАТЬСЯ.md). Техническое описание поиска — в [bot/README.md](bot/README.md).
