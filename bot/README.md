# RAG-ассистент по инструкциям 1С

Бот отвечает сотрудникам на вопросы по инструкциям 1С и показывает, из какой инструкции взят ответ. Если ответа в инструкциях нет, бот так и говорит, а не придумывает.

**Зачем это нужно.** Консультант 1С тратит много времени на одни и те же вопросы: «где кнопка», «что значит эта ошибка», «почему не видно отчёта». Инструкции обычно уже есть, но их никто не читает. Бот находит нужное место за секунду, и на типовые вопросы консультант больше не отвлекается.

## Как это работает

```
вопрос ─┬─ BM25 (точные слова) ──────────┬─ RRF → 2–4 фрагмента → Claude отвечает только по ним → ответ + источники
        └─ векторы (смысл, эмбеддинги) ──┘
```

1. **Загрузка.** Файлы из папки `docs` (Markdown, TXT, PDF, Word) делятся на фрагменты по заголовкам разделов.
2. **Поиск по словам — BM25** с русским стеммингом (snowball). Основа слова обрезается до 5 букв, поэтому «загрузить» и «загрузка», «обновить» и «обновление» считаются одним словом. Заголовок раздела весит вдвое больше текста.
3. **Поиск по смыслу — эмбеддинги.** Модель `minishlab/potion-multilingual-128M` (около 500 МБ, работает на процессоре через fastembed, без GPU и без интернета после первой загрузки). Понимает синонимы: «не грузится эксель» находит «загрузку из Excel». Векторы фрагментов кэшируются в `.cache` и пересчитываются только при изменении текстов. Сначала пробовал `paraphrase-multilingual-MiniLM-L12-v2` (220 МБ) — она находила нужную инструкцию только в 20 из 25 вопросов и не справлялась с синонимами.
4. **Объединение — Reciprocal Rank Fusion.** Списки BM25 и векторного поиска сливаются по рангам, а не по сырым оценкам: у двух методов разные шкалы, а ранги сравнимы.
5. **Решение «отвечать или нет».** Релевантность = покрытие слов вопроса (какая доля их веса нашлась во фрагментах; слова, которых нет во всей базе, весят максимально) + 2 × близость по смыслу.
   - ниже 0,9 — уверенный отказ: «в инструкциях этого нет»;
   - 0,9–1,3 — серая зона: фрагменты отдаются Claude, и модель сама решает, есть ли там ответ. Без Claude пользователь видит пометку «точного ответа может не быть»;
   - от 1,3 — уверенный ответ.
6. **Ответ.** Claude получает фрагменты с инструкцией отвечать только по ним и указывать источники.

Если fastembed не установлен, бот работает только на BM25 (порог — 40% покрытия слов).

## Качество

`python eval.py` (гибрид) и `python eval.py --bm25` (только BM25, для сравнения). Два набора вопросов:
- **настройка** — 25 вопросов по теме и 13 не по теме, на них подбирались пороги, поэтому цифры по ним оптимистичны;
- **контроль** — 10 вопросов по теме и 6 не по теме, которые при первой настройке не использовались. Оценка по ним честнее.

| Контрольный набор | Только BM25 | Гибрид |
|---|---|---|
| Нужная инструкция на 1-м месте (hit@1) | 7/10 | **10/10** |
| Нужная инструкция в первых трёх (hit@3) | 10/10 | 10/10 |
| Берётся отвечать на вопросы по теме | 7/10 | **10/10** |
| Не по теме: уверенный отказ / серая зона / уверенно ложно | 5 / 0 / 1 | 2 / 3 / 1 |

На наборе для настройки гибрид: hit@1 25/25, отвечает на 25/25, не по теме — 6 отказов, 7 в серой зоне, 0 уверенно ложных.

Что видно из цифр и почему пороги такие:
- Векторы заметно помогают на разговорных вопросах («куда пропала кнопка после установки доработки», «сколько дней товар должен лежать, чтобы попасть в отчёт»): BM25 их отбрасывал или ставил первой не ту инструкцию.
- Вопросы по теме и не по теме сильно пересекаются по оценке (зона 1,0–1,3). Сначала стоял один жёсткий порог 1,25, подобранный на наборе для настройки. На контрольном наборе бот отказал на 3 из 10 нормальных вопросов: порог был подогнан под тестовые вопросы. Поэтому сделал серую зону: поиск отдаёт кандидатов с запасом, а окончательно решает языковая модель. Найти лишнее и дать модели отсеять лучше, чем не найти нужное. Оговорка: после этого контрольный набор уже «видел» изменение, поэтому для следующих правок нужен новый.
- Оставшаяся ошибка: «Как создать новую организацию?» получает высокую оценку (1,42) — в инструкциях много слов «создать», «организация». С Claude модель должна ответить «в инструкциях нет», без Claude пользователь увидит неподходящий фрагмент.
- Неточность внутри файла: на «что значит прочерк в днях без продаж» файл найден верно, но первым идёт раздел «Настройки отчёта», а ответ — в разделе «Откуда берутся данные».

Честно о границах: база маленькая (4 инструкции), вопросы написаны тем же автором, что и инструкции, а ответы Claude в этих тестах не проверялись — оценивается только поиск. Следующие шаги:
1. Проверить ответы модели: не выдумывает ли она и правильно ли ссылается на источники (LLM-as-judge или ручная разметка).
2. Собрать тестовые вопросы из реальных обращений пользователей.
3. Попробовать модель эмбеддингов посильнее (например, `intfloat/multilingual-e5-large`, 2,2 ГБ) и переранжирование (reranker).

## Вопросы по данным 1С

Кроме инструкций бот отвечает на вопросы по живым данным 1С:Бухгалтерии 3.0 (`data1c.py`): долги покупателей (в целом, по контрагенту, просроченные, на дату), продажи за период, остатки товара, залежавшиеся товары.

```
вопрос → маршрутизатор (правила) ─┬─ про данные → проверенный запрос к 1С через COM → ответ с цифрами
                                  └─ про работу в 1С → поиск по инструкциям (RAG)
```

Почему готовые запросы, а не генерация запроса нейросетью: в бухгалтерии неверная сумма, выданная уверенным тоном, хуже, чем «не знаю». Каждый запрос написан и сверен вручную (итог по счёту 62 совпадает с выгрузкой из 1С до копейки), а из вопроса извлекаются только параметры: дата, период, контрагент, товар.

- **Свежие данные:** запрос к базе на каждый вопрос, а не кэш выгрузки. Остатки «на дату» берутся на начало следующего дня, чтобы учесть все документы этого дня.
- **Только чтение:** COM-пользователь без прав на изменение и проведение (проверено через `ПравоДоступа`).
- **Доступ:** бот отвечает только Telegram ID из `allowed_users.txt`.
- **Честность:** бот предупреждает о непроведённых реализациях, показывает переплаты отдельно, не считает просрочкой списания с расчётного счёта, помечает минусовые остатки как ошибку учёта.
- **Тесты:** `python test_data1c.py` — маршрутизация (ни один из 54 вопросов по инструкциям не уходит в данные), разбор дат и периодов, поиск контрагента по названию с другим окончанием («Северной ГЭС» → «СЕВЕРНАЯ ГЭС-2 АО»). База для тестов не нужна.

## Запуск

```bash
pip install -r requirements.txt
python rag.py index                 # что в базе знаний
python rag.py ask "Где найти загрузку счетов из Excel?"
python rag.py search "дубли при повторной загрузке"   # отладка: релевантность, слова, смысл
python rag.py chat                  # диалог в консоли
python eval.py                      # проверка качества (--bm25 — без векторов)
python data1c.py "кто нам должен"   # вопрос по данным 1С из консоли
python test_data1c.py               # тесты маршрутизации и разбора дат
python bot.py                       # Telegram-бот
```

Ключи берутся из переменных окружения или из Диспетчера учётных данных Windows (общие учётные данные):

| Что | Переменная | Учётные данные Windows |
|---|---|---|
| Ключ Claude API | `ANTHROPIC_API_KEY` | `RAG1C_Anthropic` |
| Токен Telegram-бота | `RAG1C_TELEGRAM_TOKEN` | `RAG1C_TelegramBot` |

Модель Claude задаётся переменной `RAG_MODEL` (по умолчанию `claude-sonnet-5-5`), модель эмбеддингов — `RAG_EMB_MODEL`. При первом запуске модель эмбеддингов скачивается в `.models` (около 500 МБ).

## Своя база знаний

Положите инструкции в `docs` (можно в подпапки). Документы компании кладите в `docs/private` — эта папка не попадает в git. Чем лучше разбит документ на разделы с понятными заголовками, тем точнее поиск.
